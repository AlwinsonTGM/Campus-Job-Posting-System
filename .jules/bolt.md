## 2023-11-01 - [Optimized Pagination to Prevent Memory Exhaustion]
**Learning:** The previous implementation loaded the entire jobs table into memory using `get_jobs` (without limits) and then applied `array_slice` for pagination in `student/jobs.php`. This is a classic N+1 / full-table loading anti-pattern that severely affects performance and memory footprint as the dataset grows.
**Action:** Implemented a new `get_jobs_count()` function in `includes/services/job-service.php` to fetch only the row count. Refactored `student/jobs.php` to use this count for pagination calculation and then pass `$limit` and `$offset` parameters to `get_jobs()` directly, offloading pagination work to the database engine. Next time, always ensure filtering and paginating are performed via database queries before attempting them in application memory.
