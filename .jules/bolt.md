## 2026-11-09 - Query Consolidations and Hydration layers
**Learning:** Consolidating multiple sequential database queries into a single query via a JOIN is an effective performance optimization, but caution is required when the results are passed into a hydration layer. If hydration methods (like `hydrate_category`) drop fields they don't explicitly handle, properties like `job_count` might be lost if merged directly into the row data array. Here, `hydrate_category` explicitly handles `job_count` and we avoided the regression.
**Action:** When performing JOIN-based query consolidation that introduces computed columns (e.g. `COUNT(...)`), check how the resulting row array is mapped/hydrated. Ensure that the hydration function does not strip out the new computed property, or manually re-attach the value if necessary.
